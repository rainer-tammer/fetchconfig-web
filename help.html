fetchconfig-web — Help

fetchconfig-web is a web front-end for fetchconfig, the tool that backs up network device configurations on this network. It doesn't keep its own copy of anything or re-implement the backup logic: every page runs the same fetchconfig.pl command-line tool behind the scenes, so what you see here always matches what the command line would produce.

Per-site device access

If your account is limited to one or more sites, you see and edit only the devices tagged with your site codes. The Devices, Status and Reports pages are filtered to your sites, Setup opens straight into the graphical device editor (Devices only; the Defaults tab is view-only; no Email/Reporting or Bulk edit), and a device can be assigned only to a site you hold. An administrator manages site codes and per-user assignments on the User page.

The menu bar

The bar across the top of every page holds application-style drop-down menus; click a menu name to open it and pick a function. Your username and a Log out link sit on the right. The menus are:

  • Devices — Device list (the home page after login), Backup status, Backup reports.
  • Setup devices (only if you may edit the device table) — Show device table, Edit device table, Bulk edit. A site-limited user sees only Edit device table.
  • Tools (administrators only) — each tool on its own page: Check devices for consistent backup suffixes, Check devices for empty backups, Check site assignment, Devices without backups, Empty Directory Cleanup, Orphaned Backup Cleanup, Restore device table, Template viewer, View fetchconfig log.
  • User — Change your password (everyone); Users list, Add user and Sites (administrators only).
  • Help — this page.

Logging in and out

  • Access requires a username and password. If your session has expired or you open the site fresh, you'll see the login page; enter your credentials to continue.
  • Sessions last a limited time and then require logging in again. Use Log out in the top-right when you're finished, especially on a shared computer.
  • If you don't have an account, or have forgotten your password, ask an admin user — they can create accounts and reset passwords (see User accounts).

Devices

  • The Devices page (also the home page) lists every Device-ID known to fetchconfig, read from its device table. Purely configuration entries in that table, such as the notification email: line, are not devices and are not listed.
  • The list shows each device's Model, Device-ID, Hostname and Comment. Narrow it with the model dropdown (choose one of the models in use, or “all models”) and the Device-ID, Hostname and Comment filter boxes (each matches anywhere in that column). They all combine, and Clear filter resets them. Your filter choices are remembered, so they stay in effect if you leave the page and come back.
  • Click a column header to sort by it. The Hostname column is smart about IP addresses: numeric IP addresses are sorted in real address order (so 10.1.1.1 comes after 2.5.7.8, not before it) and listed before named hosts, which sort alphabetically.
  • A statistics panel in the upper-right shows the total device count, how many devices currently match your filter, and how many devices there are per model.
  • For long lists, choose how many devices to show Per page and page through them with the First / Prev / Next / Last buttons — First and Last jump straight to the beginning or end.
  • Click a Device-ID to open its backup history.

Status

The Status page shows, for every device, the result of its most recent backup — read from the small status file each backup writes. For each device you see the start and end date/time, how long it took, whether it succeeded (State) and whether the configuration changed (Changed).

  • State is colour-coded: green for success, red for failed, blue for skipped. Changed shows changed/forced in blue and unchanged in the normal colour.
  • Devices that have no status file yet show N/A in every column.
  • Use the State and Changed drop-downs to filter the list (N/A can be filtered too); click a column header to sort; and page through long lists with the Per-page selector and the First / Prev / Next / Last buttons.
  • Click a Device-ID to open its backups — the back button there returns you to the Status page.

Backups for a device

Clicking a device shows all of its stored backups, newest first, in a table with these columns:

  • # — the backup's index (1 is the newest). Click it to view that backup's full configuration.
  • Date and Time — when the backup was taken, read from the backup file's own name. The date is shown as YYYY-MM-DD; the time includes the timezone (for example 14:35:56 CEST).
  • Size — the size of the stored configuration.
  • Path — where the file lives in the repository.

The buttons above the table act on this device:

  • Backup now — connects to the device right now and fetches a fresh configuration. You'll be asked to confirm first, because it opens a live connection to the device. While it runs, a spinner with a running timer is shown (a backup can take a while, so please be patient). The full run transcript (what it connected to, what happened, and whether it succeeded) is shown, and if a notification address is configured a backup-summary e-mail is sent, exactly as a command-line backup would. When it finishes you're returned to the backup list, which now includes the new backup.
  • Check for empty backups — asks fetchconfig to inspect the backup files already on disk for this device and report any that are zero bytes (empty). Nothing is changed; it only reads and reports, and the result is shown in the same kind of output box as Backup now.
  • Check backup suffixes — checks that this device's stored backups all use the same filename extension, and shows the full result (including a per-file breakdown when they differ). Read-only, in the same kind of output box.
  • Download latest configuration — downloads the most recent backup's configuration as a file. For normal devices it is named <Device-ID>-YYMMDD-HHMMSS.cfg (date and time taken from the backup); for the web-managed switches it is the decoded binary config file.
  • Compare selected and Side by side selected — see Comparing two backups.

Viewing a backup

  • Click a backup's # to see its full configuration in a monospaced block. For Cisco IOS, Cisco Nexus, ProCurve, Comware, Zyxel, PLANET, Aruba CX and AudioCodes Mediant SBC devices the configuration is colour-highlighted (keywords, interfaces, IP addresses, and so on) to make it easier to read; certificate dumps and banners are left un-highlighted.
  • Use the Copy button to copy the whole configuration to your clipboard in one click (the plain text is copied, without the colour markup).
  • For your protection, anything that looks like a stored password in the displayed text is masked (shown as ?***?) throughout the interface. This affects only what's shown on screen, never the backup file itself.
  • Web-managed switches without a CLI (TP-Link Easy Smart and HP ProCurve 1700) are different: their backup is a binary file, not text, so instead of showing it the page gives you a Download button. The downloaded file (named <Device-ID>-switch.cfg for ProCurve 1700, or <Device-ID>-config.cfg for TP-Link) is ready to upload to the switch's own config-restore page. For the same reason, the Compare buttons are not shown for these switches.

Comparing two backups

  • On a device's backup list, tick the checkboxes of exactly two backups, then press one of the compare buttons.
  • Compare selected shows a single-column “unified” diff — the classic before/after view with changed lines marked in place.
  • Side by side selected shows a two-column view with the older backup on the left and the newer on the right, lined up so you can read straight across. Long lines don't wrap up to a good width, and the view widens to use the screen.
  • In both views the differences are colour-coded: green for added lines, red for removed lines, and amber for changed lines. If the two backups are identical you'll be told so instead.

User accounts

  • Change your password — available to everyone. You must enter your current password, then the new one twice.
  • If your account is still using the default password, a banner appears after you log in until you change it — please pick a new password promptly.
  • If you are an admin (the admin account, or any user granted admin functions), the User page also lets you manage other accounts:
    • Add user — create a new account with a username and password. You can tick boxes to grant that user admin functions (full admin rights) and/or the right to view and edit the device table.
    • Delete — remove an account (the button next to each user). The admin account itself can never be deleted.
    • Change password (next to a user) — set a new password for that user without needing their old one. This is for resetting a colleague's forgotten password. It can't be used on the admin account — admin's own password is only changed the normal way, with the current password.
    • Grant / Revoke in the Admin functions column — give or take away full admin rights. A user with admin functions can do everything the admin account can (manage users, Tools, edit the device table).
    • Grant / Revoke in the Can edit device table column — give or take away just the right to view and edit the device table. The admin account and any admin-functions user always have both rights (shown as “always (admin)”).

Setup & editing the device table

  • The Setup devices menu appears for the admin account and for any user granted the device-table edit right. Its Show device table item shows the raw fetchconfig device table exactly as the tool reads it, with a Copy button; Edit device table opens the graphical editor and Bulk edit the raw editor.
  • Because the device table can contain device login credentials (on its default: lines), access is restricted this way and the page should be treated as sensitive.
  • Edit device table opens a structured editor with three tabs — Devices, Defaults (per model), and Email notification. Each entry is a card whose options are proper fields for the selected model; use + add option to add a recognized option, + Add device / + Add model defaults to add rows, and the × / Delete buttons to remove options or whole entries. On the Devices tab you can filter the cards by Device-ID and by comment (the filter is remembered between visits).
  • If the device table has a directory allow-list (the directory: lines, editable only on the server), the repository and template_dir options become drop-downs of the allowed directories, shown by their $ALIAS with the full path in gray. The on_fetch_run option (if allowed) is edited as a directory drop-down plus a command field; if the allow-list sets fetch_run to none it cannot be used. When a report directory is allow-listed, the Email tab gains the report options (report_dir as a drop-down, plus write_report, email_max_diff, web_report_url, report_logo and report_days). A table that uses a directory not on the list opens with a red warning but cannot be saved until it is fixed.
  • For the generic (template-driven) model, the model option is a drop-down of the templates fetchconfig reports (via fetchconfig.pl -t), scoped to the template_dir in effect for that row. Pick the template for the device, or set it once on a Defaults card for generic so all generic devices inherit it. If you change template_dir, the model list updates when you leave the field; the information icon notes that templates added on disk appear only after you reload the page.
  • The Email notification tab sets who gets the backup-summary e-mail (the from, to and smtp server, plus optional SMTP user/ password). The optional footer field is the copyright / attribution line shown at the bottom of that e-mail; leave it empty to use the default.
  • Passwords are shown masked (as \__unchanged__/). Leave a masked field alone to keep the current password; type a new value to change it. New devices need their password typed in.
  • Preview raw table shows exactly what will be written (passwords masked) without saving. From the preview you can Save changes directly — your edits are kept — or go Back to editor to keep working. The editor's Save changes without preview button skips the preview. On save, a timestamped backup of the previous table is kept first. If someone else changed the table while you were editing, the save is refused so your edits can't overwrite theirs; reload and redo them.
  • Bulk Edit admins only opens a plain-text editor showing the whole device list, one device per line, with passwords in plain text. Editing here is quick for adding or changing many devices at once, but be careful: saving replaces the entire device list with what's in the box — a line you remove is deleted, and an empty box removes all devices. The defaults and email settings are not affected. You're asked to confirm, and if any line is invalid nothing is saved and the problems are listed.

Tools admins only

  • The Tools menu item appears for admins (the admin account or any user with admin functions).

Orphaned backups — backed-up configurations still on disk whose device is no longer in the device table (for example, a device that was decommissioned or renamed):

  • Check for orphaned backups lists any orphaned backups without changing anything.
  • Delete orphaned backups permanently removes them. You are asked to confirm first, and the result (what was found and what was removed) is shown just like a backup run. This cannot be undone.

Empty directories — date or per-device directories left in the repository with no files in them. Normal backup aging and the orphaned-backup cleanup usually take care of these; this tool covers the occasional one left behind by manual file operations:

  • Check for empty directories lists any empty directories without changing anything.
  • Delete empty directories permanently removes them, after a confirm dialog, showing the result the same way. This cannot be undone.

Restore device table — lists the automatic backups of the device table (one is saved before every editor or bulk-edit save), with a current row at the top for the live table:

  • For each backup you can View its contents, Restore it (the current table is backed up first, so you can undo a restore), or Delete it. Restore and Delete both ask you to confirm.
  • To compare two configurations, tick two rows (any mix of current and backups) and press either Compare selected (a single-column list of just the changed lines) or Side by side selected (a two-column view of the full configs). The newer version is always shown in green and the older in red (current counts as newest, otherwise the later timestamp wins). Differences that are only spacing (tabs/spaces, outside quoted text) are ignored.
  • Passwords are masked by default when viewing or comparing; untick the Mask passwords checkbox to show them in plain text.
  • To clean up in bulk, enter a number of days and press Delete backups older than days: every backup older than that is removed — except the newest one, which is always kept so you never lose your last restore point. You are asked to confirm first. This control only appears when there are at least two backups.

Devices without backups — press Start scan to check every device in the table for stored backups. A progress bar shows how far along the scan is (and the button becomes Cancel scan so you can stop early), and when it finishes the devices that have no backups yet (never backed up) are listed — a quick way to spot devices that still need an initial Backup now.

Check devices for empty backups — works the same way, but lists the devices that have one or more empty (zero-byte) backup files — a fetch that connected but saved nothing. Also has a progress bar and a Cancel button.

Check devices for consistent backup suffixes — works the same way, listing devices whose backups don't all share the same filename suffix, or whose suffix doesn't match the configured one. It lists the affected Device-IDs; open a device's Check backup suffixes button to see the details.

View fetchconfig log — press Display log to open the output of the scheduled (cron) backup run on its own page, split into sections you can expand or collapse. Each section's name is green if it succeeded and red if it failed; failed sections open automatically so problems are easy to spot. Use Expand all / Collapse all to toggle everything at once.

Template viewer — press Show templates to list the generic-model templates (*.tmpl) found in the template directories that fetchconfig.pl -t reports. Each file is listed once (the same template name may legitimately appear in more than one directory, shown as separate rows with their directory), sorted by name. Click View to open a template read-only, with syntax highlighting, in the same kind of window as a configuration view.

Template editor — click Edit next to a template to open it in a split editor: the left pane is editable, the right Checked version shows it highlighted. Check syntax validates it with fetchconfig (a structural check) and shows any errors; Save only writes if the check passes and keeps the previous version as a single .tmpl.bak; Discard changes reloads the file and drops your unsaved edits; Revert to last backup version (shown when a backup exists) restores that backup; Help templates opens the template-engine manual in a new tab. Leaving the editor with unsaved changes asks for confirmation, and the Editor pane shows "Unsaved changes" while you have edits pending. A changed template should always be tested against the real device.

Getting around long pages

On pages that can get long — the device list, Setup, the device-table editor, a backup's configuration, and the side-by-side comparison — a small pair of ▲ Top / ▼ Bottom buttons floats in the bottom-right corner. Use them to jump straight to the top or bottom without scrolling.

Browser requirements

The interactive parts of this application (the device-list filter and sorting, and the device-table editor) use JavaScript that needs a reasonably modern browser. The minimum supported versions are:

  • Mozilla Firefox 50 or newer (2016)
  • Microsoft Edge 16 or newer (the Chromium-based Edge; the older “legacy” Edge is not supported)
  • Google Chrome 51 or newer (2016)

Any current release of these browsers works. Other Chromium-based browsers (Opera, Brave, Vivaldi…) and Safari 10+ also work. Static pages — logging in, viewing devices and backups — work without JavaScript, but the filter, sorting, and the device-table editor will not.
