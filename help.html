fetchconfig-web — User Guide

fetchconfig-web is a web front-end for fetchconfig, the tool that backs up network-device configurations on this network. It keeps no copy of its own and re-implements none of the backup logic: every page runs the same fetchconfig.pl command-line tool behind the scenes, so what you see here always matches what the command line would produce. This page is the complete user guide; use the contents below to jump to a topic.

Who can use a feature is marked where it matters: everyone every logged-in user, editors users with the device-table edit right, admins only the admin account or a user granted admin functions.

Part 1

Getting started

The menu bar

The bar across the top of every page holds application-style drop-down menus; click a menu name to open it and pick a function. Your username and a Log out link sit on the right, and the program icon on the far left opens the About dialog. Which menus you see depends on your permissions:

  • Devices everyone — Devices (the home page after login), Device backup status, Backup reports, Device notes.
  • Setup devices editors — Device table, Edit device table, Bulk edit devices. A site-limited editor sees only Edit device table.
  • Tools admins only — each maintenance tool on its own page (see Part 4).
  • User — Change your password and Change your email (everyone); Users, Add user and Sites (admins only).
  • Help — this guide, the two additional help sections, and About (see Help menu & About).

Logging in and out

  • Access requires a username and password. If you open the site fresh or your session has expired, you'll see the login page; enter your credentials to continue.
  • Sessions last a limited time and then require logging in again. There is also an absolute lifetime after which you must log in regardless of activity. Use Log out (top-right) when you're finished, especially on a shared computer.
  • Repeated failed logins for a username or from one address are temporarily throttled to slow down guessing; a successful login clears the counter.
  • Forgot your password? If password-reset e-mail is enabled on this installation, the login page shows a Forgot password? link that e-mails you a time-limited reset link. If it is not enabled, ask an administrator to reset it for you (see Users).

Your account & password everyone

  • User → Change your password — enter your current password, then the new one twice.
  • User → Change your email — set or update the address used for password-reset mail (when e-mail is enabled).
  • Password rules. New passwords must meet this site's policy — a minimum length and, optionally, required character types (upper-case, lower-case, digits, special characters, or a minimum number of distinct character classes). The form tells you if a password is too weak; the exact rules are set by your administrator.
  • Default-password banner. If your account still uses the initial default password, a banner appears after login until you change it. Please pick a new password promptly.

Per-site access

Accounts can be limited to one or more sites. If yours is, you see and work with only the devices tagged with your site codes:

  • The Devices, Status, Reports and Notes pages are filtered to your sites, and a device can be assigned only to a site you hold.
  • If you may edit, Setup devices opens straight into the graphical editor showing only your devices; the Defaults tab is view-only, and there is no Email/Reporting or Bulk edit.
  • An unrestricted user (the built-in admin, or anyone holding the special "all sites" code) sees everything.

Administrators manage site codes and per-user assignments — see Sites.

Devices & backups

The device list everyone

  • The Devices page (also the home page) lists every Device-ID known to fetchconfig, read from its device table. Pure configuration entries in that table, such as the notification email: line, are not devices and are not listed.
  • Each row shows the device's Model, Site, Device-ID, Hostname, Comment and a Note icon. Narrow the list with the model and site drop-downs and the Device-ID, Hostname and Comment filter boxes (each matches anywhere in that column). The site drop-down also offers (no site), which picks out the devices that carry no site= tag. The filters combine; Clear filter resets them, and your choices are remembered between visits.
  • Click the Model, Site, Device-ID or Hostname header to sort by that column (Comment and Note are not sortable). The Hostname column is smart about IP addresses: numeric addresses sort in real address order (so 10.1.1.1 comes after 2.5.7.8, not before) and are listed before named hosts, which sort alphabetically.
  • A Statistics panel (upper-right) shows the total device count, how many match your filter, and a per-model breakdown.
  • For long lists, choose how many rows to show Per page and page through with First / Prev / Next / Last.
  • Click a Device-ID to open its backup history; click the Note icon to read or edit its note.
↑ Back to top

Device backup status everyone

The Device backup status page shows, for every device, the result of its most recent backup — read from the small status file each backup writes. You see the start and end date/time, how long it took, whether it succeeded (State) and whether the configuration changed (Changed).

  • State is colour-coded: green for success, red for failed, blue for skipped. Changed shows changed/forced in blue and unchanged in the normal colour.
  • Devices with no status file yet show N/A in the date, time, duration, State and Changed columns; Site and Device-ID always show their real values.
  • Filter with the State and Changed drop-downs (N/A can be filtered too), sort by any column header, and page through long lists.
  • Click a Device-ID to open its backups; the back button there returns you to this page.

Device notes everyone

Every device can carry one free-text note — a handy place for site contacts, change reminders or quirks.

  • A paper-note icon (filled when a note exists) sits in the Note column of the device list and next to the Device-ID on the backups page. Click it to open a small dialog that loads the note, lets you edit it and a Keep flag, and saves it.
  • Devices → Device notes lists all notes you may see (Device-ID, the start of the note, the Keep flag and the last-updated time), with filters (Device-ID, Keep, date range), paging and a per-row delete.
  • Notes honour site access — a site-limited user sees and edits only notes for devices in their sites. The note text is never written to the audit log (only that a note was set, cleared or deleted).
  • The Keep flag protects a note from the admin Orphaned notes cleanup if its device is later removed.

Backups for a device everyone

Clicking a device shows all its stored backups, newest first:

  • # — the backup's index (1 is newest). Click it to view that backup's full configuration.
  • Date and Time — when the backup was taken, read from the file's own name. The date is YYYY-MM-DD; the time includes the timezone (e.g. 14:35:56 CEST).
  • Size — the stored configuration's size. A zero-byte (empty) backup row is highlighted in red so it stands out.
  • Path — where the file lives in the repository.

The buttons above the table act on this device:

  • Backup now — connects to the device right now and fetches a fresh configuration. You confirm first (it opens a live connection); a spinner with a running timer shows while it works. The full run transcript is shown, and if a notification address is configured a backup-summary e-mail is sent — exactly as a command-line backup would. Success/failure is taken from the backup's own status, so an initial backup (no previous config to compare) is reported as a success, not a failure. When it finishes you return to the backup list, now including the new backup.
  • Download — downloads the backup you picked in the table's DL column as a file; if you haven't picked one it asks you to select a configuration first. For normal devices it is named <Device-ID>-YYMMDD-HHMMSS.cfg; for the web-managed switches it is the decoded binary config file.
  • Compare selected / Side by side selected — see Comparing backups.
Note. The DL column and the Download button are shown only to a user who holds the download/copy unmasked config right; without it neither appears.

Viewing a backup everyone

  • Click a backup's # to see its full configuration in a monospaced block. For Cisco IOS, Cisco Nexus, ProCurve, Comware, Zyxel, PLANET, Aruba CX and AudioCodes Mediant SBC devices the configuration is colour-highlighted (keywords, interfaces, IP addresses, and so on); certificate dumps and banners are left plain.
  • Use Copy to copy the whole configuration to your clipboard (plain text, without the colour markup). For a user who holds the download/copy unmasked config right the button is labelled Copy unmasked and copies the unmasked configuration, fetched from the server rather than from the masked page.
  • For your protection, anything that looks like a stored password is masked (shown as ?***?) everywhere in the interface. This affects only what is displayed, never the backup file itself.
  • Web-managed switches without a CLI (TP-Link Easy Smart, HP ProCurve 1700) store a binary file, not text, so the page gives you a Download button instead of a listing (named <Device-ID>-switch.cfg or <Device-ID>-config.cfg), ready to upload to the switch's own restore page. That button too needs the download/copy unmasked config right — without it the page says you do not have the right to download device configurations. The Compare buttons are not shown for these.

Comparing backups everyone

  • On a device's backup list, tick exactly two backups, then press a compare button.
  • Compare selected shows a single-column “unified” diff — the classic before/after view with changed lines marked in place.
  • Side by side selected shows a two-column view, older on the left and newer on the right, lined up so you can read across; it widens to use the screen.
  • Differences are colour-coded: green for added, red for removed, amber for changed. If the two backups are identical you are told so instead. Whitespace outside quoted text is ignored, and passwords stay masked.

Backup reports everyone

The Devices → Backup reports page lists the HTML change-reports fetchconfig writes after a scheduled run, newest first, with View, Download and Delete per report and a Delete reports older than N days control (the newest is always kept).

  • View opens the report inside fetchconfig-web, each device shown as a collapsible section (Expand all / Collapse all), with the diff text safely escaped.
  • Download streams the original self-contained .html file.
  • Reports are masked like everything else. Seeing the full, unmasked report requires the download full report right; otherwise you see the sections for your sites.

Part 3

Editing the configuration

The device table & editor editors

The Setup devices menu appears for the admin account and any user with the device-table edit right. Because the device table can hold device login credentials (on its default: lines), treat this page as sensitive.

  • Device table shows the raw fetchconfig device table exactly as the tool reads it, with a Copy button (passwords masked).
  • Edit device table opens a structured editor with three tabs: Devices, Defaults (per model) and Email notification.

Editing devices

  • Each device is a compact collapsed row (Device-ID / Model / Site / Comment). Click Edit to expand it into a full card of the proper fields for that model, and Collapse to fold it again.
  • Use + add option to add a recognized option, + Add device / + Add model defaults to add rows, and the × / Delete buttons to remove options or whole entries.
  • Filter rows by Device-ID, Site and comment (remembered between visits); long lists paginate (100 per page) with First/Prev/Next/Last above and below.
  • Every device must have a site before the table will save.

Passwords

Stored passwords are shown masked as \__unchanged__/. Leave a masked field alone to keep the current password; type a new value to change it. New devices need their password typed in.

Allow-listed directories

If the device table has a directory allow-list (the directory: lines, editable only on the server), the repository and template_dir options become drop-downs of the allowed directories — each entry shows its $ALIAS and the directory it expands to, with the resolved path in gray beside the box. When a value matches the one on the model's default: line, a blue default flag is shown. The on_fetch_run option (if allowed) is a directory drop-down plus a command field; report options appear on the Email tab when a report directory is allow-listed. A table that uses a directory not on the list opens with a red warning and cannot be saved until fixed.

Generic (template-driven) devices

For the generic model, the model option is a drop-down of the templates fetchconfig reports, scoped to the template_dir in effect for that row. Pick the template for the device, or set it once on a Defaults card for generic so all generic devices inherit it. Templates added on disk appear after you reload the page. See Templates.

E-mail notification

The Email notification tab sets who gets the backup-summary e-mail (the from, to and smtp server, plus optional SMTP user/password) and an optional footer (the attribution line at the bottom of that e-mail; empty = default).

Saving

  • Preview raw table shows exactly what would be written (passwords masked), view-only; from there you can Save changes or go Back to editor. The editor's Save changes without preview skips it.
  • On save, a timestamped backup of the previous table is kept first, so you can always roll back (see Restore device table).
  • Reject all changes reloads from disk and discards your edits.
Note. If someone else changed the table while you were editing, the save is refused so your edits can't overwrite theirs — reload and redo them.

Bulk edit admins only

Setup devices → Bulk edit devices opens a plain-text editor showing the whole device list, one device per line, with passwords in plain text. It is quick for adding or changing many devices at once.

Careful. Saving replaces the entire device list with what's in the box — a line you remove is deleted, and an empty box removes all devices. The defaults and e-mail settings are not affected. You confirm first, and if any line is invalid nothing is saved and the problems are listed.

Templates admins only

Template-driven (generic) devices are backed up using a *.tmpl template that describes the device's login and commands. Tools → Templates lists the templates fetchconfig finds in the configured template directories, one row per file, sorted by name. The same name may appear in more than one directory (shown as separate rows with their directory).

Each row shows the template's size and modification time, a Used column (whether a device currently uses it) and the actions:

  • View — open the template read-only, with syntax highlighting.
  • Edit — open the split editor (see below).
  • Rename — rename an unused template within its directory. A popup asks for the new name (prefilled with the current one); it must be a valid model= value and must not already exist. The button is greyed out while a device still uses the template, for the same reason as Delete — the name is what the device matches on. The backup is carried over to the new name.
  • Download — save the template file to your computer.
  • Delete — remove an unused template (and its backup). The button is greyed out while a device still uses the template; what is in use is re-checked at the moment you delete.

Upload a template

Upload template adds a new .tmpl file to a template directory you choose. The file must be text and at most 100 KB, its name is the generic model= value (letters, digits, ._- and a .tmpl extension), it is syntax-checked before it is installed (a file that fails the check is never placed), and an existing name is never overwritten.

Generate a template from a HEX capture

Upload HEX capture builds a starter template from a session recorded with record-session.pl. Choose the .hex file (text, at most 1 MB; it must start with the # record-session banner), a template name, a target directory, and a syntax highlighting scheme (auto, none, or a named scheme such as cisco-ios). The capture is run through fetchconfig's generate_template.pl; the chosen scheme is written into the template header, and the result is syntax-checked and installed just like an upload (same 100 KB and no-overwrite rules).

Note. The generated template is a draft. Open it with Edit, review every line (especially any # TODO markers), and test it against the device with the generic model before relying on it.

If your administrator has installed them, the block also offers a Session recorder download — record_session.exe for Windows and the record_session.py source — for capturing the .hex session in the first place. A SHA-256 is shown beside each download. The Windows executable is unsigned, so SmartScreen or antivirus may warn on first run.

The template editor

Edit opens a split editor: the left pane is editable, the right Checked version shows it highlighted.

  • Check syntax validates the template with fetchconfig (a structural check) and shows any errors.
  • Save writes only if the check passes, keeping the previous version as a single .tmpl.bak.
  • Discard changes reloads the file and drops unsaved edits; Revert to last backup version (shown when a backup exists) restores that backup.
  • Help templates opens the template-engine manual in a new tab.
Note. The syntax check is structural only — it confirms the template's grammar, not that it actually drives your device. Always test a changed or uploaded template against the real hardware.

Part 4

Administration

Tools overview admins only

The Tools menu (the admin account or any user with admin functions) gathers the maintenance functions, each on its own page. Destructive actions always ask you to confirm and are recorded in the audit log. The rest of this part describes them.

Users admins only

  • User → Users lists username, e-mail, an Admin indicator and Reset password / Delete buttons. Click a username to open its edit page.
  • Add user — create an account with a username, password and optional e-mail. It starts with no special permissions; you are taken to its edit page to set them.
  • Edit user — one page sets the e-mail and permissions (Administrator, which overrides the individual rights; edit device table; download full report; download/copy unmasked config), shows the assigned sites with a button to the sites editor, and resets the password. Save writes everything at once; Cancel/Return warn about unsaved changes.
  • Reset password sets a new password for a user without their old one — except for admin, whose password is only changed the normal way (with the current password).
  • Delete removes an account; the admin account can never be deleted.
↑ Back to top

Sites admins only

User → Sites defines the site codes and their descriptions. A device carries an optional site= code in the device table, and each user is assigned one or more codes; a device is visible to a user only when its site is one of theirs. The reserved "all sites" code makes a user unrestricted (the built-in admin always has it). Assign codes to a user from the sites editor or the user's edit page. See also Tools → Check site assignment under Repository checks.

↑ Back to top

Audit log admins only

An append-only record of changes: device-table edits (per option, old → new), backup runs, deletes and cleanups, user and site changes, password changes (never the password itself), logo and template changes, and logins / failed logins / denied attempts. Secret values are stored as ***, and the log cannot be altered or deleted from the web UI. The viewer shows 100 entries per page (newest first) with filters, First/Prev/Next/Last navigation and a CSV export.

Login failures admins only

Tools → Login failures shows recent failed-login activity and any usernames or addresses currently throttled, with how long the throttle lasts. A successful login clears that key's counter. Use it to spot guessing attempts or a user locked out after too many tries.

Restore device table admins only

Tools → Restore device table lists the automatic backups of the device table (one is saved before every editor or bulk-edit save), with a current row at the top for the live table.

  • For each backup: View its contents, Restore it (the current table is backed up first, so a restore is itself undoable), or Delete it. Restore and Delete both confirm.
  • Tick two rows (any mix of current and backups) and press Compare selected or Side by side selected to diff them; the newer version is green, the older red, and whitespace outside quoted text is ignored.
  • Viewing and comparing mask passwords by default; untick Mask passwords to show them.
  • Delete backups older than N days removes older backups but always keeps the newest, so you never lose your last restore point (shown only when at least two backups exist).

Repository checks & cleanup admins only

These tools keep the backup repository tidy. The "check" actions only report; the "delete" actions confirm first, show the result like a backup run, and cannot be undone.

  • Orphaned backup cleanup — backups on disk whose device is no longer in the device table (decommissioned or renamed). Check lists them; Delete removes them.
  • Empty directory cleanup — date or per-device directories left with no files in them. Check lists; Delete removes.
  • Empty backup cleanup — scans every device for zero-byte backup files (a fetch that connected but saved nothing). Check lists; Delete removes.
  • Check devices for consistent backup suffixes — lists devices whose backups don't all share the same filename suffix, or whose suffix doesn't match the configured one. Press Start scan (a progress bar shows how far along, and you can Cancel) and each affected device is listed with its details.
  • Devices without backups — press Start scan (a progress bar shows how far along, and you can Cancel) to list devices that have never been backed up — a quick way to find devices needing an initial Backup now.
  • Check site assignment — lists devices with no site= tag (shown with a red placeholder in the editor), so you can assign them.
  • Orphaned notes cleanup — removes notes whose device is no longer in the table, unless the note's Keep flag is set.

Disk space admins only

Tools → Disk space shows the free space in the repository directories and the report directory, grouped by filesystem (one table per filesystem). Directories sharing a filesystem show the size figures once (black on the first, gray on the rest). It needs the optional Filesys::Df Perl module; if that is missing the tool explains how to install it.

Show fetchconfig-web.cfg admins only

Tools → Show fetchconfig-web.cfg is a read-only table of every setting in /etc/fetchconfig-web.cfg (Status, Option, Value, Default, Range), grouped by the file's # --- title --- headings, followed by settings not in the file (gray, default applies). invalid (red) marks an unknown or obsolete key, a value outside its range, or an earlier duplicate. The database password is shown as ****.

E-mail setup & report logo admins only

  • Verify email setup — checks the e-mail configuration (SMTP server, sender, authentication) and can send a test message, so you can confirm backup-summary and password-reset mail will work before relying on it.
  • Upload report logo — upload a logo image into the report directory and manage the logos already there. Accepted: .png/.jpg/.gif, 100 KB max (suggested 250×50 px); the content is verified to really be an image, and the filename is kept exactly as given (case-sensitive). In the device-table editor the report_logo option is then a drop-down of the images in that directory.

Last schedule log admins only

Tools → View last fetchconfig schedule log opens the output of the scheduled (cron) backup run on its own page, split into sections you can expand or collapse. Each section's name is green if it succeeded and red if it failed; failed sections open automatically so problems stand out. Use Expand all / Collapse all to toggle everything.

Help menu & About

The Help menu has a fixed shape:

  • Help — this user guide.
  • fetchconfig-web — additional help and fetchconfig — additional help — the extra HTML documents your administrator has installed in the help tree (the manuals, change log, licence, and so on). Each entry's label comes from the document's title, and each opens in a new browser tab. A section shows a short note when no extra documents are installed. Each help directory may hold at most 15 *.html documents; if it holds more, the section shows a single too many help documents in <directory> note instead of a menu, and your administrator needs to thin the directory out.
  • About — opens the About dialog (also reachable from the program icon on the far left), showing the program version(s), copyright, the installed fetchconfig.pl version, the run mode (CGI or FastCGI) and the licence.

Security & privacy

A few things worth knowing about how the application protects your data:

  • Password masking. Anything that looks like a stored secret is shown as ?***? throughout — config views, diffs, the device table, reports. The underlying files are never changed; masking is display-only. Seeing an unmasked config or report needs an explicit per-user right, and every such view is audited.
  • Sessions. Logins expire after a period of inactivity and an absolute lifetime. Always Log out on a shared machine.
  • Change tracking. Every change is recorded in the audit log, which cannot be edited from the web UI.
  • Safe actions. Every action that changes something is protected against cross-site request forgery, so a link on another site can't make your browser perform it. Destructive actions always ask you to confirm.

Browser requirements

The interactive parts (the device-list filter and sorting, and the device-table editor) use JavaScript that needs a reasonably modern browser. Minimum supported versions:

  • Mozilla Firefox 50 or newer (2016)
  • Microsoft Edge 16 or newer (Chromium-based; the older “legacy” Edge is not supported)
  • Google Chrome 51 or newer (2016)

Any current release of these works, as do other Chromium-based browsers (Opera, Brave, Vivaldi…) and Safari 10.1 or newer. Static pages — logging in, viewing devices and backups — work without JavaScript, but the filter, sorting and the device-table editor will not.

Getting help

For anything not covered here — a device that won't back up, a login problem, an empty or missing backup, or a feature request — contact your fetchconfig-web administrator. Deeper reference material (the full manual, the template-engine guide and the fetchconfig documentation) is in the Help menu's additional help sections when your administrator has installed it.
