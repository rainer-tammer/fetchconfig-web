2.09

Requires fetchconfig 9.72. Adds a state-machine diagram to the template viewer, colour-codes the template Used column, and closes several credential-masking gaps in the config and template views. No database change.

Template state-machine diagram

  • The Template viewer (view_template) now draws the template's login/collect state machine (Mermaid stateDiagram-v2) below the text -- the same diagram the shipped template HTML docs use. The source is built server-side from fetchconfig's own fetchconfig::model::GenericTemplateParser (loaded by absolute path from FETCHCONFIG_PATH, never copied); the browser renders it with the bundled, self-hosted js/mermaid.min.js -- fully offline, loaded only on this page. Edge labels sit on the panel background, not on white boxes.
  • New config key JS_BASE_URL (default /js). The release now ships js/ (mermaid.min.js) and fonts/ (IBM Plex Sans, needed so labels fit); copy both directories into WEB_DIR. A short note replaces the diagram if the renderer, the font, or the parser is missing, or the template fails to parse -- a stale diagram is never shown.

Templates overview

  • On Tools -> Templates (view_templates), the Used column is now colour-coded: Yes green, No red.

Credential masking (config / template views)

  • Fixed: encrypted password hashes in a viewed config could be shown unmasked. Two gaps: mask_secrets only redacted a numeric-type password (password 7 <hash>), missing the keyword-typed forms -- Zyxel password encrypted <hash>, HPE Comware password cipher <hash>, Huawei password irreversible-cipher <hash>, password hash <hash>; and the syntax highlighters isolate the encrypted blob into its own fragment and escape it alone, so the multi-token password encrypted <hash> context never reached the masker. highlight_config now masks the whole config up front, so the value is redacted regardless of how a highlighter splits the line.
  • Fixed: Hirschmann password hashes were shown unmasked. The hash is a :v<N>:<hash>: blob on a users passwd <user> :v1:<hash>: line (hirschmann model, and generic devices driven by the hirschmann template); masking now keeps users passwd <user>, the :vN: tag and the closing :, and redacts only the hash.
  • Fixed: SNMP community masking leaked on Hirschmann configs, where the community is a quoted string placed AFTER positional keywords (snmp-server community ipaddr 0.0.0.0 "secret", ... ro "secret"). The old rule masked the first token (the keyword) and left the quoted community exposed. Masking now redacts the quoted community wherever it sits on the line, and only falls back to masking a bare first-token community (Cisco/Comware) when the line has no quoted community -- no device-type detection needed.
  • Fixed: Aruba CX (aruba-cx-ssh) secrets using the ciphertext encoding keyword were mishandled. user ... password ciphertext <blob> was not masked at all, and radius-server host ... key ciphertext <blob> masked the keyword ciphertext instead of the blob. Masking now recognises the encoding keywords (ciphertext/plaintext/cipher/encrypted) after password and after key, keeps the keyword, and redacts the value -- on server lines and on the indented key form alike.
  • Fixed: Cisco Nexus (nexus-ssh) tacacs-server/radius-server lines use a numeric key TYPE before the secret (key 7 "secret"); masking redacted the type digit 7 instead of the secret. The key rule now treats a leading numeric type (as well as the Aruba CX encoding keywords) as the type, keeps it, and masks the value -- a lookahead prevents it from re-masking the visible type when the secret is the quoted token.
02

2.08

Requires fetchconfig 9.72. Adds a viewer for device debug logs and a read-only schedule tool.

Show schedule (Tools)

  • New Tools -> Show schedule (admin only). Two panels:
  • Current schedule -- lists CRON_USER's crontab (read-only) and shows the lines running FETCHCONFIG_PATH/FETCHCONFIG_BIN, parsed into schedule, a plain-language "when", the command and its log file. Commented-out fetchconfig lines are shown too, flagged disabled. Other jobs on the crontab (and any secrets on their command lines) are not shown.
  • Build a crontab entry -- pick minute / hour / day-of-month / month / weekday and copy the complete line (command from FETCHCONFIG_PATH/FETCHCONFIG_BIN, log from FETCHCONFIG_LOG). The tool never writes the crontab; you add the line yourself with crontab -e.
  • New optional config key CRON_USER -- the user whose crontab holds the job. The page shows which settings are missing if any of CRON_USER, FETCHCONFIG_PATH, FETCHCONFIG_BIN or FETCHCONFIG_LOG is unset.
  • Reading another user's crontab goes through the existing privileged helper (TEMPLATE_HELPER + sudo) -- a new read-only list-cron subcommand -- because the cron spool directory is root-owned. No new sudoers rule is needed; the helper is redeployed. The target user comes only from the config and must exist (getpwnam).
  • Helper v1.7: list-cron forces LC_ALL=C and an absolute crontab path, so the viewer works on a non-English Linux host (RHEL/SLES/Debian) where cron's "no crontab for &lt;user&gt;" message would otherwise be localized and misread.

Device debug logs

  • View on the Device backup status page, in a new Debug column shown to admins and holders of the new read_debug right. Greyed out when the device has no <device-id>.debug file.
  • The buttons key on the file, not on the debug option -- a device set back to debug=off keeps the log written while it was on.
  • The viewer highlights the Net::Telnet hex dump, with SEND / RECV badges, a per-direction tint and a rule where the direction turns.
  • Sent only / Received only filter in the browser; Transcript view reassembles the bytes into a readable session.
  • SSH log hidden / shown -- the ssh client's own stderr, hidden by default. Classified by complement (not a hex line, not a # marker), so it can never hide device traffic; the # markers always stay visible.
  • Copy returns the log as shown, with the original < / > markers: the badges are CSS generated content, not markup.
  • New Tools entry Device debug logs: every device that has one, plus Delete all debug logs.
  • Views and deletions are audited (view_debug, delete_debug, delete_all_debug).

Debug log permissions

  • New per-user right read_debug -- view device debug logs, for the user's own sites. Not implied by being site-unrestricted, unlike the other per-user rights: a debug log can contain the device password in clear text, so it must be granted explicitly.
  • Download (raw file) and Delete stay admin only.
  • Buttons: Device backup status has View only; Tools has View | Download | Delete; the viewer has Download and Delete for admins.
  • The viewer returns to the page it was opened from.

Other

  • Device backup status gains Site and Device-ID filters, with the same behaviour as the device list (site exact, device-id a case-insensitive substring). Filters persist in the existing cookie.
  • Device backup status and Tools -> Device debug logs are sorted by device-id, case-insensitively, instead of device-table order.
  • Fixed: sorting a column on Device backup status reordered only the rows on the current page. It now sorts the whole table, as the device list already did.
  • The user editor's permission boxes are wider, so no permission label wraps.
  • The Device backup status filter row uses the same control sizes as the Devices page.
  • Fixed: the stylesheet is now cache-busted by APP_VERSION_INTERNAL (the true shipped version), not by APP_VERSION. APP_VERSION is display-only and config-overridable, so it may be any string without affecting the CSS.
  • Per page on Device backup status now offers All/10/20/40/80/160, defaulting to 40, as the device list does.

Viewer size limits

  • Under 2 MB in full; 2--16 MB as the first and last 1 MB with ----- content cut because of a 2 MB viewing size limit ----- between them; over 16 MB not displayed or downloaded (it can still be deleted).
  • Chunks are cut on line boundaries, so no half hex-dump line is rendered.

Reading root-owned debug logs

  • fetchconfig creates <device-id>.debug as root, mode 0600, so the web-server user can neither read nor delete it (unlink needs write permission on the root-owned repository directory).
  • With TEMPLATE_HELPER set, the viewer reads and deletes through that helper. It is the one the template editor already uses -- no new sudoers rule; redeploy the helper.
  • Without it the buttons explain the permission problem instead of failing with a generic error.
  • Helper v1.5 adds read-debug and delete-debug, hardened like the template commands: absolute path, no .., must end .debug, plain file only. read-debug takes a byte window, so a large log is not pulled through the pipe in full.

Upgrading: run fetchconfig-web-dbupdate-2.08.sql once, and redeploy the helper.

Security

  • A debug log is a full session transcript and can contain device credentials. Secret masking cannot help -- it matches key=value, while a password in a hex dump is split across 16-byte lines as hex and ASCII. The controls are the admin-only gate and fetchconfig's own print_secret().
  • The delete path takes a device id only. The file path is re-derived from the device table, symlinks are refused, and a missing file is not an error.
  • Read errors show generic text; the reason goes to the audit log.

2.07

Requires fetchconfig 9.72. Template management on the Templates page, plus a server-side input-validation audit and its fixes.

Upgrading: add the second sudoers rule -- without it every template write fails -- and redeploy the helper (now v1.3):

code 
<webuser> ALL=(root) NOPASSWD: /usr/local/fetchconfig/fetchconfig-web-install-template.pl

Requires

  • fetchconfig 9.72 (was 9.71).
  • prompt_settle removed from the generic model -- dropped in 9.72, it was a no-op. An existing prompt_settle= is preserved as an "(unrecognized)" chip, not discarded. Unrelated to prompt_settle_ms, which stays.
  • Perl floors lowered to what the code uses: CGI 4.31, DBD::Pg 3.0.0, DBI 1.614. The old floors made perl Makefile.PL fail on stock RHEL 9 and SLES 15. Security guidance moved to INSTALL.md, where it belongs -- a floor rejects a patched vendor build and accepts an unpatched CPAN one.

Template management

  • Upload, download, rename and delete templates. Uploads are name-checked, capped at 100 KB, syntax-checked before install, and never overwrite (atomic). Rename and delete are refused for a template in use by a device, re-checked server-side.
  • New Used column on the Templates page.
  • Generate a template from a HEX capture via fetchconfig's generate_template.pl, stamping the chosen syntax_style. The result is a draft -- review it against the device.
  • Session-recorder downloads (record_session.exe, record_session.py), each shown only when present, with size, date and a cached SHA-256. Not shipped; build the exe from fetchconfig's contrib/windows.
  • Helper v1.3: adds install-new, delete and rename (v1.2), and refuses a symlinked .bak on revert (v1.3). The existing sudoers entry covers every subcommand. Helper errors in the UI are condensed to the single error line instead of its full --help.

Security and validation

An audit asked whether all input is validated on the server or only in the browser. It was not. Fixed:

  • Per-site scope on the device page. The scope check keyed on the action name, and that page is reached with no action, so a site-limited user could read any device's backups by typing the URL. Unmasked downloads were gated separately and never exposed.
  • Unknown model no longer destroys the stored enable password. The secret write-back keyed on the catalog type; for a model outside the catalog it wrote the mask string into the table as the password. No attacker needed -- the editor keeps an unknown model, so a table from a newer fetchconfig lost the secret on any ordinary save. It now keys on the mask alone.
  • Report logo upload/delete, and report delete/prune, are admin-only. All four handlers were reachable by any logged-in user; the admin-only menu was the only gate. Controls are hidden for non-admins and the handlers check.
  • lock_dir is checked against the directory allow-list (opt-in: without a lock line it stays unrestricted, as documented).
  • Option values are checked against their catalog type -- the same sets the widgets offer, case-insensitively -- and report_logo against valid_logo_name(). Behaviour change: a table hand-edited to carry a value outside the documented set (say changes_only=yes) is now refused on save, with an error naming the record, option and accepted values.
  • Unknown models and option keys are still accepted and labelled "(unknown)" / "(unrecognized)", so a table written by a newer fetchconfig stays editable -- but checked for illegal content: an option name cannot carry = or ,, and no value may contain a control character.
  • Bounded the editor's form indices. A crafted <key>__<n> pre-extended a Perl array; the record loop also re-read every parameter per record.
  • Site codes reject , = # -- they are written as site=<code> into the device table.
  • Template rename without the helper is now atomic (link(), not check-then-act).
  • Name and token validators anchor on \z, not $, which also matches before a trailing newline.
  • An oversized POST now returns 413 instead of a misleading "No file was selected."
  • Removed the legacy set_download_full_report / set_download_full_config handlers -- dead since 1.63; do_user_save covers the same rights and still emits the same audit actions.
  • run_check_empty() removed (dead).
  • Global $CGI::POST_MAX of 2 MB.
  • New suites t/C8-server-validation.t, t/C9-lock-dir-optin.t and t/D0-helper-revert.t, each verified to fail against the previous code.

Documentation

  • The device-table editor and bulk editor now POST url-encoded, not multipart. CGI.pm's start_form defaults to multipart/form-data, which costs about 86 bytes of framing per field -- neither form has a file input, so that was pure overhead against $CGI::POST_MAX. The same table is now 4-6x smaller (1000 collapsed devices: 196 KB -> 34 KB), raising the ceiling from roughly 10,600 to 55,000 collapsed devices. Upload forms stay multipart, as they must.
  • A device-table save that would exceed the request limit is now refused in the browser, with the estimated and permitted sizes, instead of being discarded by CGI.pm and losing every edit in the form. The estimate carries a 20% margin (the browser picks its own multipart boundary, and non-ASCII values encode to a variable number of bytes). Advisory only -- the server enforces $CGI::POST_MAX regardless.
  • Over-sized uploads are now refused in the browser, before the request starts. Once an upload is under way an over-sized one cannot be reported properly -- the server answers while the browser is still sending, the connection is reset, and the browser shows its own error page whatever ErrorDocument is configured (Apache bug 17722). The three upload forms now carry their cap as data-max-upload and a file over it is refused with a styled message and no upload. This is a convenience, not a control: the server re-checks every upload and remains the only thing that decides. The caps live in one place (UPLOAD_MAX_LOGO / _TEMPLATE / _HEX), used by both the forms and the handlers, so the hint cannot drift from the rule.
  • INSTALL's web-server setup consolidated into one Step 7. The Apache configuration was spread over Steps 4, 7, 7a, 7b and 7c and shown six times over. It is now a single complete virtual host, given once in 2.4 syntax, with the three lines that differ on 2.2 listed beside it -- plus TLS, the FastCGI choice, the size limits, the plain-CGI variant and how to verify.
  • INSTALL's Apache snippets now cover both 2.2 and 2.4: the Step 4 sample used Require all granted, which is 2.4-only and makes 2.2 fail to start with Invalid command 'Require', and the mod_fcgid <Directory> block carried no access directive at all, so a copied vhost answered 403 on either branch.
  • mod_fcgid deployments must raise FcgidMaxRequestLen (default 131072 = 128 KB) to 2097152, matching $CGI::POST_MAX. Below that, mod_fcgid rejects an upload before the script runs -- a bare 500, with exceeds MaxRequestLen in the error log -- so a 100 KB logo or template fails and a 1 MB HEX capture can never succeed. Documented in Step 7, in a callout beside the timeout requirements, and in the verification checklist. Plain CGI is unaffected.
  • Audited against the source: the missing sudoers rule, per-distribution package names for RHEL 9 / SLES 15 / Ubuntu, bcrypt (not $apr1$) password storage, the DB-backed login throttle, a documented action that never existed, and assorted stale names and values.
  • New Installing newer modules from CPAN section in INSTALL.md.
  • The application is not a single self-contained file: the logo and login icon are inlined for load performance, while the stylesheet, fonts, favicon, help tree and back.jpg are deployed under WEB_DIR. Document headers now read Perl FCGI/CGI, and the prose no longer describes the app as plain-CGI-only.
  • Help menus list up to 15 files (was 10).

2.04

Bug fix: Backup Now no longer reports a false failure on an initial backup.

  • "Backup now" now takes its pass/fail verdict from the device's per-run .status file (backup_state) -- the same signal fetchconfig records and the summary email and backup overview already use -- instead of scraping the log for an error: line. An initial backup logs a benign <model>: there is no latest config (there is no prior config to diff against) while the fetch still succeeds; that no longer trips a "Backup run FAILED" message.
  • A hard error (timeout / fork failure) is still a failure. When no .status file is available (an older fetchconfig, or a crash before it is written) the log is still scanned as a fallback, with that benign line ignored, and a genuine failure (bad enable password, unreachable device -> backup_state = failed) is still reported.

2.03

Help menu restructured.

  • The Help menu is now served from a help tree, <WEB_DIR><HELP_BASE_URL> (new HELP_BASE_URL config key, default /help). help.html lives directly in it.
  • Two "additional help" sections -- "fetchconfig-web - additional help" and "fetchconfig - additional help" -- are built by scanning the fetchconfig-web/ and fetchconfig/ sub-directories of the help tree for *.html documents. Each document's menu label is taken from its <title>; entries are sorted by label and open in a new tab. You curate each menu simply by placing the files you want exposed in the directory. The sub-directories are read-only to the application (no web-server write access needed).
  • A sub-directory that is missing or holds no .html shows a muted "No additional helpfiles available - see INSTALL.md"; one with more than ten .html files shows a single "too many help documents in &lt;dir&gt;" placeholder.
  • New About entry at the bottom of the Help menu, opening the same dialog as the title-bar program icon.
  • The bundled help pages now carry a uniform <title> in the house style (fetchconfig-web &mdash; <Subtitle>, em dash), so the auto-derived menu labels are consistent.
  • The previous flat Help-menu list of fixed document names in WEB_DIR was removed. See the Upgrading section of INSTALL for the migration steps.

2.00

Major release consolidating 1.53-1.63. Requires fetchconfig 9.69 or newer. Database: adds users.download_full_config and the device_notes table (run fetchconfig-web-dbupdate-1.62.sql on an existing install).

Highlights

  • User management redesigned: slim user list -> per-user edit page (identity, permissions, site access, password); one save writes all fields and logs one audit line per changed permission. Permissions live in one place only.
  • Device notes: a per-device free-text note (optionally "keep"), with a notes viewer and an orphaned-notes cleanup tool.
  • Unmasked-config right: the config view is always masked; a per-user download_full_config right gates the unmasked copy/download, both audited.
  • Device locking (fetchconfig 9.69): lock / lock_dir / lock_retry / lock_retry_time device options, lock_dir resolved against a "directory: lock" allow-list; a lock-skip shows as the "skipped" state.

Security

  • Host-header reset-link poisoning fixed: reset links use a configured SITE_URL only; no SITE_URL -> no reset mail.
  • Session ids, reset tokens and password salts come from /dev/urandom with a loop on short reads and fail closed (no weak rand() fallback).
  • Reset tokens hashed with SHA-256; login/reset throttling hardened (no timing oracle, no FastCGI-worker exhaustion); forgot-password audits every outcome.
  • Password policy (length and character classes), config-file permission check, HSTS/Cache-Control headers, and a login-failures viewer.
  • Config masking extended to switch-config secret forms (SNMP community, RADIUS/TACACS keys, WPA passphrases, Aruba CX controller/auth-server keys) and to Cisco IOS hashed secrets -- "secret <type> <hash>" and "password <type> <hash>" (enable secret, username secret/password), in both the plain and syntax-highlighted backup views.

Other

  • All notification emails (test, password reset, admin verify) share one modern HTML style (program icon via a CID image so Thunderbird/Outlook show it inline) plus a plain-text part; the reset mail has a "Set a new password" button.
  • Consistent UI: every tool/editor/compare/result page uses the green tool-section box; the Devices list uses a blue box with the statistics box beside it; menu labels match the page titles.
  • The stylesheet moved out of the CGI into an external, cacheable file, fetchconfig-web.css, linked with a ?v=<version> cache-buster and served from WEB_DIR via CSS_BASE_URL. Config reworked into web paths: WEB_DIR (filesystem root, presence checks), BASE_URL (URL root), and CSS_BASE_URL/FONT_BASE_URL/ IMAGE_BASE_URL sub-paths (defaults /css, /fonts, /images). HELP_DIR, HELP_FILE and HELP_BASE_URL are removed (help.html is a fixed name under WEB_DIR); a missing stylesheet shows a red "directories not configured" banner. The login backdrop image loads from BASE_URL + IMAGE_BASE_URL + /back.jpg. Ship fetchconfig-web.css into WEB_DIR/css (see INSTALL).
  • Fixed report deep links from notification emails: opening a ?action=view_report&file=... link while logged out now returns to that exact report after authenticating (the file= argument was previously dropped across the login). The argument is re-validated with the action's own validator so only a safe report file / template path is carried; valid_report_name was tightened to a safe character set.
  • Removed the DEVICE_ID_FIELD config key: the Device-ID is always the second column of a device-table line, so the knob only confused (and the main parser ignored it anyway).
  • The log viewer is renamed "View last fetchconfig schedule log" (menu, page and box title); the box title now shows the log's date and time.
  • Tool-output pages (Backup Now, orphaned/empty backup and directory check/delete) now use the full window width; the dark result box fills it and scrolls long lines internally instead of forcing the whole page to scroll.
  • The "Backups for <device>" page drops the "Check for empty backups" button (and its now-unused checkempty action); a 0-byte (empty) backup row is highlighted red instead. The site-wide Tools -> Empty backup cleanup is unaffected.
  • Ships favicon.ico.
  • FastCGI deployment (FCGI optional).
  • Every function now carries a uniform header block.

1.51

  • Fixed: user add/change/delete, permission changes (edit/admin rights, site assignment, report-download right) and site add/edit/delete were not recorded in the audit log -- the database handle was disconnected before the audit call, so the write was silently lost. audit() now detects a dead handle (via ping) and opens its own connection, and those callers no longer pass the closed handle. The set_user_sites entry now records which site codes were added/removed (and old->new), and the add_user entry spells out the rights. The report-download right change now logs grant vs revoke (like the edit/admin right changes) instead of a flat "updated" message.
  • The device-table external-change tripwire no longer fails silently: if its app_state record cannot be read/written (e.g. the table is missing or not granted to the web user), a footer warning is shown instead of the check quietly doing nothing. A real content change is logged as external_change on login and editor open; an mtime-only touch is intentionally ignored. The detection now also shows the user a visible amber banner (on editor open, and once on the first page after login via a one-shot app_state notice), not just an audit-log row. The banner links to the audit log only for admins (a user with just the edit-device-table right sees the notice without the link, since they cannot open the audit log). On the device-table editor the banner also notes that the editor has loaded the changed table, so the user is editing the current on-disk content (not a stale copy). The bulk editor does the same: it now runs the tripwire on a fresh open and carries the same "editing the current content" note. (Fixed a regression where a stale DBI errstr on the shared handle made app_state reads look like failures, silently disabling the tripwire even though the token was stored.)
  • Audit log. New append-only audit_log table (and a small app_state table) recording state-changing actions: device-table saves (one row per changed option, old -> new), restores, backup runs, deletes/cleanups, user add/ change/delete, password changes/resets (never the password), site changes, logo upload/delete, template save/revert, plus logins / failed logins / logout and denied attempts (CSRF, out-of-site). Secret option values (pass/enable/SNMP community) are stored as ***.
  • Immutability (Level B): the web DB user gets INSERT + SELECT on audit_log only -- no UPDATE/DELETE -- so the log cannot be altered or erased from the app; only a DBA can. Audit writes are fail-open: on failure the action still completes and a yellow warning is shown in the footer.
  • External-change tripwire: the app records the device table's content token after its own writes and, on login and when the editor opens, logs an external_change entry if the table was modified outside the application.
  • Tools -> Audit log viewer (admin only): 100 rows/page, newest first, fetched by AJAX (the table is never sent whole), First/Prev/Next/Last navigation, filters (user/action/object/text/date range) and CSV export.
  • New standalone PostgreSQL 8.2-compatible script fetchconfig-web-audit.sql to add the audit tables to an existing database (also folded into fetchconfig-web-dbupdate.sql); fresh installs get them via fetchconfig-web-dbsetup.pl.
  • Fixed: audit entries for actions that did not pass an explicit user (e.g. empty/orphan cleanup, backup_now) logged the session id instead of the username -- current_user() returned the session id (current_session's first element) rather than the username. The Audit log page now uses the wide layout and its table sits in a scroll wrapper inside the green box (the box fills the width and contains the table instead of overflowing).
  • Audit log page: added a Reload button (Filter | Clear | Reload | Export CSV) that re-fetches the current page.
  • New documents: LICENSE-ADDITIONS.md/.html (GPLv3 Section 7 additional terms -- EU/German liability and warranty adaptation, severability, German/EU governing law) and PRIVACY.md/.html (GDPR notes; the software runs on the operator's own system and the operator is the data controller; the provider stores no data).
  • New fetchconfig-web-clean-audit.pl: prune old audit-log rows with a privileged DB role (-t days to keep, -l preview, -s print the create-role SQL, -l requires -t, -u/-p or prompt for credentials, -v/-h). The prune is itself recorded in the audit log (action audit_prune, including the -t value), so the create-role SQL grants SELECT + INSERT + DELETE on audit_log (and the id sequence). The prune never deletes the audit_prune records themselves, so the pruning history is kept, and it writes a prune record only when rows were actually deleted (a run that removed nothing logs nothing). A failure to WRITE that prune record (e.g. the role was granted INSERT on audit_log but not USAGE on audit_log_id_seq) is now reported instead of being silent: the delete still succeeds and a warning names the missing grant. Version/copyright follow the config overrides.
  • Added cpanfile (mirrors Makefile.PL prerequisites) to document the Perl module dependencies and support cpanm --installdeps .. (GitHub's dependency graph and Dependabot do not support CPAN, so no dependabot.yml is shipped.)
  • Audit log viewer: the Old -> New column wraps long values -- after the arrow when present (>60 chars), otherwise at the nearest whitespace near 50 chars (40-60), or a hard break at 60 if there is no whitespace there.
