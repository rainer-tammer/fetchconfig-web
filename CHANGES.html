fetchconfig-web -- change log

2.02

Requires fetchconfig 9.71 or newer.

  • The debug=on|off session-log toggle is now available on every model in the device-table editor (it became a universal option in fetchconfig 9.71). It was moved into the editor's common option set, so the previous per-model debug entries were removed.
  • Minimum fetchconfig raised to 9.71 (was 9.69).
  • Reworded the "device table modified outside fetchconfig-web" editor warning for clarity; the audit-log link text is now "audit log". The notice now also shows the on-disk file owner and the table's last-written date/time (yyyy-mm-dd / HH:MM:SS).

2.01

Maintenance release.

  • Fixed report deep links from notification emails: opening a ?action=view_report&file=... link while logged out now returns to that exact report after authenticating (the file= argument was previously dropped across the login). The carried argument is re-validated with the target action's own validator so only a safe report file / template path is kept; valid_report_name was tightened to a safe character set.

2.00

Major release consolidating 1.53-1.63. Requires fetchconfig 9.69 or newer.

Database: adds users.download_full_config and the device_notes table

(run fetchconfig-web-dbupdate-1.62.sql on an existing install).

Highlights

  • User management redesigned: slim user list -> per-user edit page (identity, permissions, site access, password); one save writes all fields and logs one audit line per changed permission. Permissions live in one place only.
  • Device notes: a per-device free-text note (optionally "keep"), with a notes viewer and an orphaned-notes cleanup tool.
  • Unmasked-config right: the config view is always masked; a per-user download_full_config right gates the unmasked copy/download, both audited.
  • Device locking (fetchconfig 9.69): lock / lock_dir / lock_retry / lock_retry_time device options, lock_dir resolved against a "directory: lock" allow-list; a lock-skip shows as the "skipped" state.

Security

  • Host-header reset-link poisoning fixed: reset links use a configured SITE_URL only; no SITE_URL -> no reset mail.
  • Session ids, reset tokens and password salts come from /dev/urandom with a loop on short reads and fail closed (no weak rand() fallback).
  • Reset tokens hashed with SHA-256; login/reset throttling hardened (no timing oracle, no FastCGI-worker exhaustion); forgot-password audits every outcome.
  • Password policy (length and character classes), config-file permission check, HSTS/Cache-Control headers, and a login-failures viewer.
  • Config masking extended to switch-config secret forms (SNMP community, RADIUS/TACACS keys, WPA passphrases, Aruba CX controller/auth-server keys) and to Cisco IOS hashed secrets -- "secret <type> <hash>" and "password <type> <hash>" (enable secret, username secret/password), in both the plain and syntax-highlighted backup views.

Other

  • All notification emails (test, password reset, admin verify) share one modern HTML style (program icon via a CID image so Thunderbird/Outlook show it inline) plus a plain-text part; the reset mail has a "Set a new password" button.
  • Consistent UI: every tool/editor/compare/result page uses the green tool-section box; the Devices list uses a blue box with the statistics box beside it; menu labels match the page titles.
  • The stylesheet moved out of the CGI into an external, cacheable file, fetchconfig-web.css, linked with a ?v=<version> cache-buster and served from WEB_DIR via CSS_BASE_URL. Config reworked into web paths: WEB_DIR (filesystem root, presence checks), BASE_URL (URL root), and CSS_BASE_URL/FONT_BASE_URL/ IMAGE_BASE_URL sub-paths (defaults /css, /fonts, /images). HELP_DIR, HELP_FILE and HELP_BASE_URL are removed (help.html is a fixed name under WEB_DIR); a missing stylesheet shows a red "directories not configured" banner. The login backdrop image loads from BASE_URL + IMAGE_BASE_URL + /back.jpg. Ship fetchconfig-web.css into WEB_DIR/css (see INSTALL).
  • Fixed report deep links from notification emails: opening a ?action=view_report&file=... link while logged out now returns to that exact report after authenticating (the file= argument was previously dropped across the login). The argument is re-validated with the action's own validator so only a safe report file / template path is carried; valid_report_name was tightened to a safe character set.
  • Removed the DEVICE_ID_FIELD config key: the Device-ID is always the second column of a device-table line, so the knob only confused (and the main parser ignored it anyway).
  • The log viewer is renamed "View last fetchconfig schedule log" (menu, page and box title); the box title now shows the log's date and time.
  • Tool-output pages (Backup Now, orphaned/empty backup and directory check/delete) now use the full window width; the dark result box fills it and scrolls long lines internally instead of forcing the whole page to scroll.
  • The "Backups for <device>" page drops the "Check for empty backups" button (and its now-unused checkempty action); a 0-byte (empty) backup row is highlighted red instead. The site-wide Tools -> Empty backup cleanup is unaffected.
  • Ships favicon.ico. FastCGI deployment (FCGI optional). Every function now carries a uniform header block.

1.51

  • Fixed: user add/change/delete, permission changes (edit/admin rights, site assignment, report-download right) and site add/edit/delete were not recorded in the audit log -- the database handle was disconnected before the audit call, so the write was silently lost. audit() now detects a dead handle (via ping) and opens its own connection, and those callers no longer pass the closed handle. The set_user_sites entry now records which site codes were added/removed (and old->new), and the add_user entry spells out the rights. The report-download right change now logs grant vs revoke (like the edit/admin right changes) instead of a flat "updated" message.
  • The device-table external-change tripwire no longer fails silently: if its app_state record cannot be read/written (e.g. the table is missing or not granted to the web user), a footer warning is shown instead of the check quietly doing nothing. A real content change is logged as external_change on login and editor open; an mtime-only touch is intentionally ignored. The detection now also shows the user a visible amber banner (on editor open, and once on the first page after login via a one-shot app_state notice), not just an audit-log row. The banner links to the audit log only for admins (a user with just the edit-device-table right sees the notice without the link, since they cannot open the audit log). On the device-table editor the banner also notes that the editor has loaded the changed table, so the user is editing the current on-disk content (not a stale copy). The bulk editor does the same: it now runs the tripwire on a fresh open and carries the same "editing the current content" note. (Fixed a regression where a stale DBI errstr on the shared handle made app_state reads look like failures, silently disabling the tripwire even though the token was stored.)
  • Audit log. New append-only audit_log table (and a small app_state table) recording state-changing actions: device-table saves (one row per changed option, old -> new), restores, backup runs, deletes/cleanups, user add/ change/delete, password changes/resets (never the password), site changes, logo upload/delete, template save/revert, plus logins / failed logins / logout and denied attempts (CSRF, out-of-site). Secret option values (pass/enable/SNMP community) are stored as ***.
  • Immutability (Level B): the web DB user gets INSERT + SELECT on audit_log only -- no UPDATE/DELETE -- so the log cannot be altered or erased from the app; only a DBA can. Audit writes are fail-open: on failure the action still completes and a yellow warning is shown in the footer.
  • External-change tripwire: the app records the device table's content token after its own writes and, on login and when the editor opens, logs an external_change entry if the table was modified outside the application.
  • Tools -> Audit log viewer (admin only): 100 rows/page, newest first, fetched by AJAX (the table is never sent whole), First/Prev/Next/Last navigation, filters (user/action/object/text/date range) and CSV export.
  • New standalone PostgreSQL 8.2-compatible script fetchconfig-web-audit.sql to add the audit tables to an existing database (also folded into fetchconfig-web-dbupdate.sql); fresh installs get them via fetchconfig-web-dbsetup.pl.
  • Fixed: audit entries for actions that did not pass an explicit user (e.g. empty/orphan cleanup, backup_now) logged the session id instead of the username -- current_user() returned the session id (current_session's first element) rather than the username. The Audit log page now uses the wide layout and its table sits in a scroll wrapper inside the green box (the box fills the width and contains the table instead of overflowing).
  • Audit log page: added a Reload button (Filter | Clear | Reload | Export CSV) that re-fetches the current page.
  • New documents: LICENSE-ADDITIONS.md/.html (GPLv3 Section 7 additional terms -- EU/German liability and warranty adaptation, severability, German/EU governing law) and PRIVACY.md/.html (GDPR notes; the software runs on the operator's own system and the operator is the data controller; the provider stores no data).
  • New fetchconfig-web-clean-audit.pl: prune old audit-log rows with a privileged DB role (-t days to keep, -l preview, -s print the create-role SQL, -l requires -t, -u/-p or prompt for credentials, -v/-h). The prune is itself recorded in the audit log (action audit_prune, including the -t value), so the create-role SQL grants SELECT + INSERT + DELETE on audit_log (and the id sequence). The prune never deletes the audit_prune records themselves, so the pruning history is kept, and it writes a prune record only when rows were actually deleted (a run that removed nothing logs nothing). A failure to WRITE that prune record (e.g. the role was granted INSERT on audit_log but not USAGE on audit_log_id_seq) is now reported instead of being silent: the delete still succeeds and a warning names the missing grant. Version/copyright follow the config overrides.
  • Added cpanfile (mirrors Makefile.PL prerequisites) to document the Perl module dependencies and support cpanm --installdeps .. (GitHub's dependency graph and Dependabot do not support CPAN, so no dependabot.yml is shipped.)
  • Audit log viewer: the Old -> New column wraps long values -- after the arrow when present (>60 chars), otherwise at the nearest whitespace near 50 chars (40-60), or a hard break at 60 if there is no whitespace there.
  • render-doc.py now also renders the GPLv3 LICENSE verbatim to LICENSE.md and LICENSE.html (preformatted, not reflowed).
  • The Help menu is now a dropdown: Help (help.html or internal), Documentation fetchconfig-web, Documentation fetchconfig, GNU GPL v3, Additional terms, and Privacy policy -- each static doc shown only if present in the help directory and opened in a new browser tab (the Help page itself opens in the same tab). Help config split: HELP_DIR (filesystem dir, for the existence check) + HELP_FILE (filename) + HELP_BASE_URL (URL base, for the menu links), with the old full-path HELP_FILE still accepted. Removed the obsolete "Fetchconfig manual" topic from help.html. The internal help fallback is now a short notice that help.html is missing from the web help directory and should be copied from the source package, rather than a duplicate feature description.
  • Audit log viewer: added a second First/Prev/Next/Last pager at the bottom (left-aligned, like the other pages); both pagers stay in sync. Added the floating Top / Bottom scroll buttons that the other pages have.
  • Email config: a gray hint after the "to" field notes that multiple recipients may be separated by ";".
  • Backup Now now has a wall-clock timeout (BACKUP_TIMEOUT, default 120s, 0 disables): a device that never responds no longer blocks the request. On a timeout the run is terminated and the partial tool output is still shown. The Backup Now page now shows the tool output whenever there is any -- even on an error/timeout (previously output was hidden on any error). Success is judged from the output (fetchconfig always exits 0): an "error:" line, or a "backup_state=failed" line in the stats block, means FAILED. The audit log records OK/FAILED accordingly; the meaningless exit status is no longer logged.
  • Replaced the per-device "Check devices for empty backups" tool with an "Empty Backup Cleanup" tool (modelled on Empty Directory Cleanup): a Check (fetchconfig.pl -Z) and a Delete (-Z -D) that scan all devices at once for zero-byte backups, with a spinner and the tools output layout. The spinner now stays on the result page until the (slow) -Z scan finishes: the page renders the spinner immediately and fetches the result fragment by AJAX (with a no-JS fallback). The delete does the same -- its AJAX POST carries the CSRF token (and the action in the body, so the multipart POST reaches the right handler instead of falling through to the Devices page), and its no-JS fallback is a POST form. Success is taken from the summary line (rc 1 = "found some", not an error). The delete is audited. The per-device -z check remains on each device's backup page. (The old all-device scan code -- check_empty_one / device_empty_status -- was removed.) Help and README updated accordingly (empty backups is a cleanup, not a scan; dropped from the MAX_PARALLEL_SCAN tool list). The Tools menu entry is now "Empty Backup Cleanup" (the old "Check devices for empty backups" label was removed).
  • Version bumped to 1.51.

Session files now carry a 5th line (login time); legacy 4-line files load and are upgraded in place.

  • Restore device table now participates in the concurrency guard: its confirm shows the live table's last-modified time/age, and the restore takes the writer lock and re-checks the staleness token under it, so a restore started against a table that has since changed is refused instead of silently discarding the newer change (Gap C, Layers 1-2).

  • The Status page table is wrapped in the same green "tool-section" box as the Tools pages, for a consistent look.

+ The template viewer (Tools) and the new Reports page use the backup-table

style: the green "tool-section" box with a bordered list and View/Edit/

Download/Delete as buttons.

+ New "Reports" page (top menu, between Status and Setup): lists the HTML

change-reports fetchconfig writes into the email: report_dir, newest first,

with styled table and button actions; View (collapsible per-device diffs,

parsed and escaped, Expand/Collapse

all), Download (streamed as an attachment through the CGI), Delete, and a

"delete reports older than N days" prune. All file access goes through the

login since the web server cannot read the report directory directly.

  • Removed the per-device "Check backup suffixes" button from the backups page; the Tools page "Check devices for consistent backup suffixes" covers this.

+ New template-driven "generic" model: a device selects model=generic and a

model=<template> option, with model= rendered as a drop-down of the templates

fetchconfig reports. Adopts fetchconfig's tab-separated --list-allowed-dirs /

-t output and its exit codes (a missing directory blocks the editor and

viewer with the fetchconfig output; "stay" is highlighted as a transition).

+ Tools: "Template viewer" lists the generic-model templates read-only with

syntax highlighting, and "Template editor" edits them in a split view with a

syntax check, single .tmpl.bak backup, revert, and unsaved-changes guard.

Template writes go through a new privileged helper

(fetchconfig-web-install-template.pl, run via sudo, configured by

TEMPLATE_HELPER); non-regular files (symlinks, hard links) are refused.

+ Directory allow-list: the device table may carry "directory:" lines

(repository / template / fetch_run / report, each $ALIAS + path), read

server-side from

the table so they cannot be forged and written back verbatim, armored with

"must be edited on the server" comments (shown red in the Setup view). When

present, the editor's repository=, template_dir= and on_fetch_run fields

become drop-downs of the allowed aliases (expanded path shown in gray;

on_fetch_run splits into a directory + a command field), saved lines store the

$ALIAS, and a table using a directory not on the list cannot be saved.

+ New config keys FONT_BASE_URL, IMAGE_BASE_URL, HELP_BASE_URL (URL-path bases,

validated at startup) and TEMPLATE_HELPER; integer config keys now report a

clear configuration error on an invalid value instead of silently defaulting.

+ A device-table save is now validated by fetchconfig (-t and

--list-allowed-dirs against the exact bytes) before being written, so an

invalid table never reaches disk; the Bulk edit page runs the same checks.

+ Added a Makefile.PL and a t/ unit-test suite (Test::More), plus

imageconvert.pl

(encodes an image as a base64 Perl snippet, with README.imageconvert).

  • Model-option audit against the fetchconfig README (timeout optional everywhere, plus per-model option corrections).
  • Custom confirmation dialogs replace the browser's confirm(); wider, full-width layout for the config/compare/log/backup views; editor, preview and bulk-edit action buttons moved to the top of the page.
  • Documentation restructured into parts with a table of contents and quick start. Minimum required fetchconfig version is now 9.65; fetchconfig-web is 1.15.

1.12

+ New models: "mediant-sbc" (AudioCodes Mediant SBC, Cisco-style CLI;

user/pass/enable, optional transport=ssh|telnet|auto, adds an enum_transport

editor field and an AudioCodes-syntax highlighter) and "nexus-ssh" (Cisco

Nexus / NX-OS over SSH, with a dedicated NX-OS highlighter).

+ Tools: run the device scans (without-backups / empty / suffix) in parallel,

controlled by MAX_PARALLEL_SCAN (1..5, default 1); the progress line shows how

many scan processes are active. Fixed intermittent scan failures by rewriting

session files atomically (temp file + rename) and hardening child-process I/O

(EINTR retry, checked waitpid, ASCII-safe JSON); each failed device now shows

why.

+ Tools: new "Empty Directory Cleanup" (fetchconfig.pl -e / -e -D) and "Check

devices for consistent backup suffixes" (fetchconfig.pl -s), plus a per-device

"Check backup suffixes" button; and, under Restore device table, "Delete

backups older than N days" (always keeps the newest).

+ Login page shows a full-page backdrop image (IMAGE_BASE_URL/back.jpg) behind

the title bar, login box and bottom-centred footer. New config keys

FONT_BASE_URL and IMAGE_BASE_URL (URL-path bases for fonts and images).

  • Config: the fetchconfig executable is now two keys -- FETCHCONFIG_PATH (install dir, also used to find Constants.pm) and FETCHCONFIG_BIN (executable name); the old single full-path form is no longer accepted. The page footer shows the installed fetchconfig version, and a warning banner appears if it is older than the required minimum or cannot be determined.

+ Device-table editor: numeric time fields show their unit (s / ms); the Email

tab gained optional "port" and "tls" (off|starttls|ssl) options; the

aruba-cx-ssh model gained optional prompt_settle_ms. Fixed: coriant-8600 no

longer wrongly requires an "enable" password.

+ Backup-filename parsing tolerates fetchconfig's filename_append_suffix (the

backup list dates/times stay correct and "Download latest configuration"

keeps a dotted suffix, else .cfg). Empty-backup check also recognises

fetchconfig's newer "N zero-byte backup(s)" message.

  • Security hardening: device ids/usernames reject a leading "-" (central valid_id, so an id can't be read as a CLI option); unsalted {SHA} password hashes removed ($apr1$/$1$/$5$/$6$/DES kept); session cookie SameSite=Lax; uniform 2s delay on failed logins; Backup-Now cleartext temp file auto-removed on exit; SESSION_TTL is now an idle timeout; numeric/boolean config keys validated with fallback to defaults.

+ Licensed under the GNU GPL v3+ (headers in both programs, LICENSE file, README

section). render-doc.py runs on Python 3 and 2.7. Documentation reworked

(added a "How fetchconfig.pl is invoked" reference and a security overview;

wider HTML manual). APP_VERSION is a built-in constant, overridable by the

config.

(DBI/DBD::Pg). Standalone setup script fetchconfig-web-dbsetup.pl creates

(key = value); only the config-file path, app title, and cookie name stay

hard-coded.
